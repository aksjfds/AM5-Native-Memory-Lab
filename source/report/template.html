本机性能与路径级参数定位

这份报告现在如何定位问题

性能数字来自本地原生程序实际执行的内存访问。本版新增读写方向切换间距扫描、短窗口尾延迟探针，以及基于重复样本噪声、回归拟合和正交对照的自动优先级。

诊断完全由本次实测样本生成，不使用 profile.ini 中的时序数值来给参数组打分。当前仍未实现物理地址→DRAM Bank/Row 映射和 UMC/IBS 硬件计数器，因此不会把路径级证据伪装成某一项 BIOS 时序的独立贡献。

参数组优先级：由本次实测自动生成

只有能在本轮建立可重复差分证据的路径才进入优先级评分。no_evidence 表示本轮没有发现该路径值得优先处理；unresolved 表示有现象，但由于缺少 Bank/Row 映射或硬件计数器，禁止定责。

读写方向切换扫描

保持每轮总读取字节与总写入字节为 50/50，只改变“连续读一段 → 连续写一段”的分组大小。分组越小，单位数据中的读写方向切换越频繁。报告根据每轮的 elapsed/logical_bytes 与 transition_events/logical_bytes 做线性拟合，得到有效的 ns/transition 斜率和 R²。

这比旧版仅比较 64B 与 64KiB 两点更有可识别性，但 CPU 乱序、store buffer 与 IMC 请求重排仍存在，所以结果是“有效切换敏感度”，不是 tWTR/tRDWR 的直接周期读数。

负载下访问延迟

横轴是后台线程实际产生的逻辑 GB/s。混合读写和纯读的相同线程数对照会进入“读写方向切换路径”的辅助证据。

串行延迟与独立访问链

单链是依赖读取延迟；多链的 ns/access 是并行后的摊销时间。八链相对理想 8× 的效率用于判断“并行路径是否存在明显缺口”，但缺少 Bank 映射时不直接定责 tFAW/tRRD。

短窗口尾延迟探针

每个计时窗口只执行 64 次依赖随机读取，避免旧版 8192 次访问窗口把短时 stall 过度平均。本版记录 P50/P95/P99/P99.9/Max。

该探针只证明存在尾延迟，不能确认尾部就是 DRAM Refresh。没有 UMC refresh 计数器和周期事件相关性之前，tRFC/tREFI 不进入自动优先级评分。

L1／L2／L3 范围工作集

单线程工作集测试，用于区分缓存与主存路径。没有缓存命中计数器，因此不宣称严格隔离某一级缓存，也不直接对应 AIDA64 缓存分数。

当前版本能回答与不能回答的问题

能够回答

当前配置下，哪条访问路径出现了可重复、显著的性能敏感度；哪些候选参数组值得优先做下一步 BIOS A/B；哪些路径本轮没有证据。

仍不能回答

单独把 tRP 48 改成 44 会提升多少、是否稳定；某次 stall 是否由 Refresh 引起；某个虚拟地址究竟落在哪个 Bank/Row。精确单项收益需要真实参数读回和反事实 A/B，Bank/ACT 类归因还需要物理地址映射或 UMC 计数器。
